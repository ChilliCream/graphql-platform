Allocation scope is process-wide, including managed allocations on asynchronous continuation threads. The NET6_0_OR_GREATER implementation calls GC.GetTotalAllocatedBytes(precise:true) at both boundaries. A current-thread fallback exists only in an older-target conditional path and is not the loaded net8 library. Reported per-operation bytes divide the difference by TotalOperations and round to the nearest integer, ties to even. Negative differences are clamped to zero; that code path does not prove any observed result was negative. The old allocation-quantum filter does not apply to the current .NET10 runtime. Async migration alone is not grounds to discount these totals. [GcStats implementation](https://github.com/dotnet/BenchmarkDotNet/blob/1e8238ef6c08e18821edae83ac8d6b0a2bb1bb98/src/BenchmarkDotNet/Engines/GcStats.cs)

The diagnostic is one additional workload iteration after the timing stages. Engine forces GC.Collect, waits for finalizers, then collects again before the diagnostic, even when timing uses WithGcForce(false). Boundary reads surround WorkloadAction; iteration setup/cleanup and the pre-diagnostic collections are outside these reads. TotalOperations is invocation count times OperationsPerInvoke, here1×1000=1000, not twelve timing iterations or all warmup requests. GC counts describe this diagnostic interval only. Independent background allocations in the same process are included; this is a scoped process delta, not per-object attribution. [Engine implementation](https://github.com/dotnet/BenchmarkDotNet/blob/1e8238ef6c08e18821edae83ac8d6b0a2bb1bb98/src/BenchmarkDotNet/Engines/Engine.cs)

InProcessEmit still constructs the normal engine through its factory and invokes Engine.Run. Its generated workload waits for awaitables through GetResult, so these bounds include completion of the async benchmark action. No alternative current-thread allocation reader is selected by this toolchain. [Runnable emission](https://github.com/dotnet/BenchmarkDotNet/blob/1e8238ef6c08e18821edae83ac8d6b0a2bb1bb98/src/BenchmarkDotNet/Toolchains/InProcess/Emit/Implementation/Emitters/RunnableEmitter.cs)

Full JSON contains raw Gen0/Gen1/Gen2 collection counts, TotalOperations and rounded BytesAllocatedPerOperation. Displayed Gen columns normalize collection counts per1000 operations; with our1000-operation diagnostic these happen to equal the raw counts numerically. Raw //GC output retains the unrounded allocated-byte total after nonnegative clamping. Preserve it alongside JSON. A surprising zero or inconsistent result needs source/mechanism and repeated-control interpretation, not an assumption that async allocations were omitted.
