The per-request source-client scope allocates dictionary bookkeeping even when execution uses only one client. Reset also snapshots the dictionary values on this common path.

This PR stores the first key/client pair in an immutable entry and uses the existing dictionary for additional keys. It preserves creation locking, operation-type keys, reentrant factories, asynchronous disposal, failure cleanup and callback snapshots.

### Verdict

**Retained as a bounded allocation improvement.** Single-client cycles save 520 B of scoped bookkeeping (560 B to a 40 B holder). The pooled scope retains one additional reference, estimated at 8 B, about 32 KiB for the default 4,096 contexts per schema; reset clears it. The matched HTTP runs did not repeat the earlier +23.45% CPU/+24.27% p99 observation: p95, p99 and p99.9 stayed within or below the baseline ranges. The first run also had an isolated 102.837 ms maximum, retained in the full distribution. The first CPU result was 1.02% above the highest baseline; the second was inside the baseline range, with no repeated adverse pattern.

Baseline CPU drifted downward 4.01%, so these results do not establish CPU equivalence or a gateway CPU, throughput or latency gain. Exact default-policy HTTP allocation totals remain unvalidated. The supported benefit is lower allocation in the measured single-client scope path.
