Prototype and consumption contract
The patch adds AsyncMethodBuilder(typeof(PoolingAsyncValueTaskMethodBuilder<>)) to the two protected OnExecuteAsync overrides, plus a required using directive. Both node classes are sealed. ExecutionNode.ExecuteAsync is their sole source caller and awaits the returned ValueTask<ExecutionStatus> exactly once with ConfigureAwait(false). The fire-and-forget outer ExecuteAsync remains unchanged and unpooled. Source-result ownership, exception handling, cancellation, result merging and plan format are unchanged.

Pinned runtime contract: https://raw.githubusercontent.com/dotnet/runtime/v10.0.12/src/libraries/System.Private.CoreLib/src/System/Runtime/CompilerServices/PoolingAsyncValueTaskMethodBuilderT.cs . GetResult returns boxes in a finally block. ReturnToCache clears the generated state and captured ExecutionContext and resets the value-task source. Each generated method has one thread-local cache slot per participating thread and one slot per logical processor. There is no fixed global participating-thread bound. Retained objects do not retain prior request state after reset, but retained box count/capacity and cache miss rates still require assessment. These statements summarize the cited runtime implementation, not a measured heap snapshot.
