# C11: Reuse the synchronous transport JSON formatter

Status: 43 focused correctness tests passed; independent engine overlay ready for benchmark preparation. No performance measurement or benefit claim. This isolated worktree starts at `43a8dca2bd479ddc411d832ed97e42d9fcc8bd85`.

The warm TestQuery allocation profile attributes 386 ticks and 41,141,568 weighted sampled bytes, approximately 1.1909% of sampled bytes, to `JsonWriter` construction in `DefaultGraphQLHttpClient.CreateJsonContent`. The actual operation makes seven HTTP source requests. These observations establish recurrence, not exact allocated bytes or calls from the sample count.

The prototype lends one thread-local formatter to the synchronous body-writing call. The slot is empty while leased, so same-thread reentry gets a different formatter. Before returning it, finally clears null-ignore state and resets it to an empty sink, removing the outgoing buffer reference. The outgoing pooled byte writer retains its existing lifetime across HTTP send. No formatter lease spans an await.

Only the sealed built-in `OperationRequest`, `VariableBatchRequest`, and internal `AliasBatchedRequestBody` receive cached formatters. Public arbitrary request bodies retain fresh formatters. `OperationBatchRequest` also retains a fresh formatter because its public child-operation collection can contain a custom implementation that keeps the writer. The fixed transport encoder/options remain unchanged. Whitelisted bodies write pre-serialized variable segments and do not enable deferred property-name buffering.

This is distinct from abandoned C1, which investigated representation-store scratch and dedup state across representation builds. C11 changes a different caller and a synchronous formatter lifetime; it retains no representation chunks, network buffer, request store or dedup table. The authored-PR exclusion audit found no matching transport-formatter reuse experiment. C12 changes internal asynchronous send dispatch in an independent worktree and is not included here.

Correctness cases cover overlapping HTTP sends and outgoing-buffer lifetime, same-thread reentry through query memory access, reset after query memory access throws, and custom native-batch children retaining distinct writers. Independent source review found no ownership blocker for the explicit whitelist. The initial 43-test run had one incorrect assertion that invalid UTF-8 must throw under the existing writer options; its log/XML are retained. The corrected deterministic memory-access exception case and all other 42 cases pass. The production Release build has zero errors and three existing target/ASP.NET deprecation warnings; the test-only rebuild has zero errors and two existing deprecation warnings.

The benchmark handoff reuses the actual `HttpSourceSchemaClient` plus sealed default client fixture from C4, with the candidate engine applied independently to the pinned baseline dependencies. The outgoing content is consumed, results are fully read and disposed, and arenas seal before cleanup. Native BenchmarkDotNet MemoryDiagnoser and default-GC elapsed measurements are required; separately calibrated allocation is corroboration, not default-policy total allocation. A removed formatter object is an upper bound on net saving, which must include lease/reset overhead and retention. Unclear ownership, negligible allocation savings, meaningful added cost or inconclusive evidence stops the candidate without repeated attempts to obtain a favorable result.
