C12: Internal asynchronous HTTP send boxes
Status: QUEUED_FOR_MICRO, unmeasured.
Baseline: 43a8dca2bd479ddc411d832ed97e42d9fcc8bd85.

Evidence: The existing warm allocation profile contains 765 allocation ticks attributed to DefaultGraphQLHttpClient.ExecuteInternalAsync. Ticks are sampling observations, not allocated object counts or exact byte totals. The exact baseline engine 9c436477e63d9c7f5c8668dcd75fec9771f500a5e71b14a1f02dd0bcf8fe6c5b has an 80-byte generated state struct on .NET 10.0.12. Object header, Task/base fields and alignment are additional. The layout helper measures no timing or allocations.

Hypothesis: An internal pooled ValueTask send overload can remove the default transport wrapper box on repeated genuinely asynchronous Fusion HTTP sends. The underlying HttpClient Task and request/response allocations remain. This is independent of C8 node builders and C11 JSON writer reuse.

Scope: FUSION-only internal overload in the linked DefaultGraphQLHttpClient source. The existing public SendAsync method and its private Task implementation remain unchanged. HttpSourceSchemaClient uses the internal overload only when the concrete client is sealed DefaultGraphQLHttpClient and request.Uri is non-null. All custom clients and null-Uri cases retain the existing public Task call. Four internal call sites immediately await once: ordinary single, subscription, native batch stream and alias batch stream. No ValueTask is stored, converted to Task or awaited more than once in production.

Contract: The internal overload retains the writer and request message across HttpClient.SendAsync, ResponseHeadersRead, version policy, callback order and ConfigureAwait(false). It captures the resolved request Uri exactly once. Existing response ownership when OnMessageReceived throws is unchanged. The public route supports repeated Task awaits without conversion. The duplicated send wrapper is a maintenance cost.

Retention: The pinned runtime pooling builder resets the state machine and ExecutionContext after GetResult before cache return, including fault/cancellation completion. Caches are specific to the generated method/state machine, with one thread-local slot per participating thread and one slot per logical processor; there is no fixed global thread-count bound. Request objects can remain live while a send is genuinely in flight; pooled boxes may remain retained after completion. Do not claim a process-wide retained-byte cap or a measured allocation saving from the struct layout alone.
Runtime source: https://raw.githubusercontent.com/dotnet/runtime/v10.0.12/src/libraries/System.Private.CoreLib/src/System/Runtime/CompilerServices/PoolingAsyncValueTaskMethodBuilderT.cs
