Each multi-chunk parse constructs one SequenceSegment object for every used geometric chunk.
MemoryArena rents consecutive slabs from a byte-array page when other rentals do not interleave.
If every used chunk shares the same array and exactly adjacent offsets, the parser can receive
one ReadOnlySequence over that byte range. Original stored segments and packed locations remain
unchanged. The single-chunk fast path and all noncontiguous cases retain their existing behavior.
An affected parse removes N temporary segment objects, with N the used chunk count. The shared
4KB and32KB fixtures use three and six chunks. Their exact byte/elapsed effect requires measurement.

Risks and exclusions
The adjacency scan adds work before the original fallback. Concurrent arena rentals or page
boundaries can make chunks noncontiguous. Strict ReferenceEquals(array) and exact offset checks
are required; equality of contents or touching virtual addresses is insufficient. A one-segment
reader still produces absolute byte offsets, which ParseJson maps into original geometric chunks.
CreateFilledReader/ParseFilledElement must preserve those offsets for batched documents.
EXCLUSION-AUDIT.txt and the exact saved PR10523 diff establish the mechanism differs from the
forbidden ReadOnlyMemorySegment struct-layout compaction. Independent review confirmed this.
