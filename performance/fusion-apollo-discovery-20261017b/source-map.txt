2. Cold plan construction, excluded unless profile proves recurrence
   Execution/Nodes/ApolloOperationExecutionNode.cs:70 rewrites the synthetic
   lookup with LookupEntityQueryRewriter and parses the outgoing operation.
   Its constructor compiles RepresentationShapeBuilder.Build once. Batch nodes

3. Representation creation, recurring per active entity fetch
   ApolloOperationExecutionNode.OnExecuteAsync ->
   OperationPlanContext.CreateRepresentationVariableValue (:481) ->
   Results/FetchResultStore.RepresentationValue.cs:
   CreateRepresentationVariableValue (:122) -> CollectTargetElements ->
   BuildRepresentationValue (:277) -> TryWriteRepresentation (:408) ->
   TryBufferRepresentation (:436) -> TryWriteShapeLevel (:580) ->
   TryAppendRepresentation (:535) -> TryDeduplicateRepresentation (:559).

   CollectTargetElements (FetchResultStore.cs:905) traverses target paths with
   reusable double buffers, list unrolling, and an existing PropertyLookupMemo
   per field segment. All representation production is protected by the
   request store lock. BuildRepresentationValue creates one ChunkedArrayWriter,
   VariableDedupTable, and JsonWriter per active lookup, rents result paths,
   initializes dedup capacity, and serializes every representation before hash
   and byte comparison. Unique serialized data is copied to the request-wide
   variable writer. Duplicate entity paths accumulate separately.

   RepresentationShapeNode already stores UTF-8 names. TryWriteShapeLevel does
   one property resolution per required shape node, preserves nullability,
   source aliases, abstract runtime types, nested requirements and list shapes.
   Source-only observation: these lookups do not use the memoized overload that
   CollectTargetElements uses. Whether property resolution matters is unknown.

   CompleteRepresentationVariableValue (:373) copies the populated EntityResultPath
   span to an immutable exact-length array. RepresentationPathAccumulator.ApplyTo
   (:1879) creates one CompactPath[] for duplicate target paths. Above 256 distinct
   representation slots it also creates three int[] scratch arrays. The primary
   benchmark's actual distinct counts must be observed before this matters.

   The imported snapshot/defer path is separate (:155, :188) and reads stored
   JSON requirements. It is a relevant fallback correctness case if shared code
   changes, but the unchanged TestQuery has no @defer.

4. Error attribution arrays
   Execution/RepresentationValue.cs:19 ToVariableValues creates an exact-length
   VariableValues[] per distinct entity; its values all reference the same
   combined JSON payload. Single Apollo nodes invoke it eagerly before transport.
   Batch BuildRequests (:303) invokes it for every active member. The success
   merge uses RepresentationValue.ResultPaths directly. VariableValueSets are
   used for transport/store exception attribution, missing batch results and
   PendingMerge.AddErrors. A separate one-element requestVariables array is
   necessary to route the combined representations as ONE operation.
   Any deferred-attribution change must preserve exceptional paths and ownership.
   This is a source hypothesis only; no allocation or CPU benefit is claimed.

5. Entity batching and outgoing request encoding
   Execution/Nodes/ApolloOperationBatchExecutionNode.cs:138 rents four temporary
   arrays (definitions, representations, per-entity variables, receipt flags),
   builds immutable requests, and sends ISourceSchemaClient.ExecuteBatchAsync.
   Request operation text and parsed documents are cached in the node.

   Execution/Clients/HttpSourceSchemaClient.cs:94 selects single stream or alias
   variable batching; :160 selects alias operation batching or native transport.
   Alias batching is enabled only when capabilities allow it and the relevant
   native request/variable batching support is absent. Unsupported request
   batching falls back to sequential isolated requests. Never assume concurrent
   per-member transport from the node name.

   HttpSourceSchemaClient.AliasBatching.cs creates AliasBatchItem[], shared-variable
   list, AliasBatchedRequestBody and SourceSchemaResult[] on each alias batch,
   writes variables/operation aliases, then splits the result with shared document
   ownership. Shared operation structure exists in cached UTF-8 documents but
   the alias request body still performs composition per dispatch. Original query
   uses no client variables, so shared-variable demotion is unlikely to matter.

6. Response parsing, completion and output
   HttpSourceSchemaClient reads downstream responses into SourceResultDocument
   using request memory. SourceResultDocument.Parse and MetaDb methods are the
   profile signatures for tokenization/metadata work. AliasBatchResponseSplitter
   creates per-member views rather than independent reparsed documents.

   Apollo result delivery -> PendingMerge.RepresentationSingle ->
   ExecutionState.EnqueueMerge -> OperationPlanExecutor.ExecuteQueryAsync
   (:1137) drains merges -> PendingMerge.Apply ->
   OperationPlanContext.AddRepresentationResult ->
   FetchResultStore.AddRepresentationResult (:28) -> SaveRepresentationResult
   (:1427) -> SaveSafeResult (FetchResultStore.cs:701, :750) ->
   ValueCompletion.BuildResult (:54), TryCompleteList (:967),
   TryCompleteObjectValue (:1255).

   Entity response length must exactly match distinct representations. Each
   deduplicated response is merged into its primary path and all additional
   paths. This preserves selected data while avoiding duplicate source fetches;
   repeated destination completion can still dominate nested duplicate shapes.
   ValueCompletion already has scalar fast paths, cached object contexts,
   abstract type memoization and source snapshots. CompositeResultDocument.WriteTo
   and JSON formatting remain shared Apollo/native final-response work.

7. Concurrency and ownership
   ExecutionState.StartNode calls BeginExecute directly. Query roots start in
   parallel, then the executor drains ConcurrentQueue<PendingMerge> and completed
   results before scheduling dependents. AsyncAutoResetEvent signals the loop.
   Merges are serialized through this executor loop; the store's lock does not
   prove contention. Runnable CPU, scheduler time, idle waits and contention need
   separate interpretation. No lock-replacement candidate is warranted by source.

   AddRepresentationResult registers SourceSchemaResult with request memory and
   returns representation path segments in its finally block. PendingMerge's
   canceled/unmerged branch has an existing TODO about path segments only being
   reclaimed with the store; any buffering/array reuse must audit cancellation,
   exceptions, request cleanup and maximum retained capacity.
