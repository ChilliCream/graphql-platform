Independent source review by execution_discovery found no concurrency or context blocker under the existing single-awaiter contract. Clearing scheduled fields before invocation permits immediate re-await and requeue; the old callback retains only locals, so later field writes are not clobbered. ExecutionContext capture stays at the same Set or OnCompleted scheduling point as QueueUserWorkItem. Pooled ExecutionState ownership requires active consumer completion before reset, unchanged by this patch.

An unmeasured refinement using ICriticalNotifyCompletion was investigated and rejected before implementation. Its UnsafeOnCompleted path could avoid redundant producer-context capture, but this changes observable producer AsyncLocal propagation when the awaiting method started with ExecutionContext flow suppressed. The original safe captured-context variant is retained. No candidate production source or frozen engine changed, and no measurement was rerun.

The upcoming gate includes native BenchmarkDotNet MemoryDiagnoser output as explicitly requested by the user, plus calibrated allocation validation. Native diagnoser totals require corroboration and do not establish CPU savings. The shared actual-executor fixture must verify genuine suspension and preserve separate baseline, C6 and C8 engine overlays.
