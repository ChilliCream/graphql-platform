Preparation only until the root selects the final survivors and grants an exclusive measurement window. C3 owns this runner. The baseline/C2 owner reviews it independently. No run is authorized by creating a plan file.

`vendor/` preserves the published baseline runner, analyzer, focused driver, original benchmark driver, queries and full response oracles from baseline evidence commit `ef9fc1159a5a7a980754ebd42b511030320482cd`. `campaign.py` reuses its process startup, affinity, runtime counters, 100 ms observations and owned PID/start-identity cleanup. Its timing override selects local frozen oracles, enforces fixed-rate accounting and records boundaries. Original k6 is byte-identical (`b967285db74541fd9b29ab68522b6f5902de4caf7e43946dab183205bc88ea6e`).

Prepare under `flock -s -o /workspaces/platform-1/perf/fusion-common-path.lock`. Provide `prepare --survivors C3 --plan <outside-this-source-directory.json>`, or `--survivors C3,C2` plus the independently accepted `--c2-gateway`, `--c2-dll` and `--c2-pdb`. Preparation starts no HTTP or application processes. It records every gateway/source/runner/oracle/tool hash and rejects candidate changes beyond the execution DLL/PDB. The plan must remain outside this source directory to avoid self-referential hashes.

The root-approved execution command is `flock -x -o /workspaces/platform-1/perf/fusion-common-path.lock taskset -c 0,8 python3 campaign.py execute --plan <frozen-plan> --output <new-empty-result-directory> --root-grant <approval-reference>`. The parent/monitor affinity is asserted and its PID/start identity recorded. The complete source/fixture/tool identity is rechecked before any process starts. Existing output is rejected. Failed or partial campaigns stop and remain intact; this script has no resume/retry path. SIGINT/SIGTERM unwind the active session and clean only owned processes. Child load timeouts are the published duration plus 120 s, including original setup. Expected full campaign duration is 23–25 min for C3 alone or 32–35 min for both survivors.

Every new gateway first passes complete response comparison for original TestQuery, entities9 and ordinary, then runs the original 30 s warmup. At 0 ms source delay: original 50 VU/30 s, entities9 50 VU/20 s, ordinary 5,000 arrivals/s for 20 s with 50 fixed VUs. At 4 ms: original 50 VU/30 s, exact original 60 s burst at peak 500 VUs, then 20 s observed idle. Original setup is unchanged, including 1,000 sequential burst setup requests. The supplementary ordinary script preserves query, Authorization, setup and oracle semantics but uses a constant-arrival-rate executor; require 100,000 measured iterations, 100 setup requests and zero drops. It is a regression/headroom control, not a capacity measurement or a continuation of the saturated discovery ordinary configuration.

Run `analyze.py <results>` only after measurement ends, under the shared lock. The published analyzer retains exact native/setup/summary accounting, matched CPU/request windows, runtime interval-rate checks, resource peaks and p99/p99.9 rank neighbors/clusters. The wrapper adds both adjacent controls, the full control envelope/time order, approximate burst stage bins and observed retention windows. Stage bins use the first observed iteration start, not exact scheduler callbacks. Memory observations cover pre-setup, burst including setup, idle and final 5 s idle. Runtime gauges can be stale since the last GC; RSS is not retained heap. No forced GC or profiler is added.

The only established C3 benefit entering this gate is 2,680 scoped B saved in the original representation sequence. HTTP outcomes must be interpreted with all controls and resource limitations. No timing improvement is assumed and no automatic acceptance threshold is hidden in the analyzer.

The whole-session budget is 50 minutes: a 48-minute workload alarm reserves 120 seconds for cleanup. Cleanup defers that alarm while applying the existing 8-second graceful / 3-second forced deadline to at most seven live owned children, plus the 2-second monitor join, then restores any remaining alarm. The runner records the requested bound and actual whole-session elapsed time. Phase markers also print progress; no extra profiling or measured workload changes are introduced.
